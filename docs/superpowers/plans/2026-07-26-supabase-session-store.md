# Supabase Session Store Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace SQLite-backed session/message storage with a Supabase-hosted Postgres store reached via a direct `psycopg` connection, deleting SQLite from the codebase entirely — production code and tests.

**Architecture:** One new store class, `_SupabaseSessionStore`, implements the same five-method contract SQLite's `_SessionStore` did, so `ConversationManager` (used by `chat`/`research`/`pdf`) needs zero interface changes. `coding`'s separate, duplicate SQLite implementation is deleted outright and unified onto the same shared `ConversationManager`. All ~20 existing tests that patched a temp-file SQLite store swap to a new in-memory `FakeSessionStore` with an identical interface.

**Tech Stack:** `psycopg[binary,pool]` (psycopg 3) for a direct transactional Postgres connection — not `supabase-py`/PostgREST, since `save()` needs a real multi-statement transaction. Supabase CLI + Docker for local integration testing.

**Spec:** `docs/superpowers/specs/2026-07-26-supabase-session-store-design.md`

## Global Constraints

- No data migration from `data/sessions.db` — Supabase starts empty. The old SQLite file is left on disk, untouched, unreferenced by any code path after this plan.
- No authentication. Exactly one seeded `profiles` row with a hardcoded UUID constant `_DEFAULT_PROFILE_ID = "00000000-0000-0000-0000-000000000001"`, referenced from code, never a config value.
- No silent fallback. A missing/unreachable Supabase surfaces as a `RuntimeError` (or, on the Research SSE path, a structured `{"type":"error","code":"storage_unavailable",...}` event) — never a degraded mode, never a fallback to SQLite.
- `_SupabaseSessionStore`'s constructor performs no I/O. Connection/config validation happens only inside `_get_pool()`, on first real use — construction must never raise, or `_store = _SupabaseSessionStore()` at module import time breaks every test's ability to monkeypatch `_store` before it runs.
- `content` is stored as `jsonb`, wrapped in `psycopg.types.json.Jsonb(...)` on every insert (string or dict) — Postgres/psycopg does not infer this automatically.
- The pool must be created with `row_factory=dict_row` (`from psycopg.rows import dict_row`) — without it, `row["role"]`/`row["content"]` raise at runtime, since psycopg's default row factory returns tuples.
- `save()` runs as a single transaction: upsert session → `select ... for update` → delete existing messages → bulk-insert new ones (skipped if the list is empty) → bump `revision`/`updated_at`. Do not call `conn.commit()` manually inside a `with pool.connection() as conn:` block — psycopg3's connection context manager commits automatically on clean exit and rolls back automatically on any exception raised inside the block; an explicit mid-block commit would split this into two transactions and defeat the atomicity this design exists for.
- `unique (user_id, client_key)`, not a bare `unique(client_key)` — scoped to the (currently single, future-multi) user.
- RLS is enabled on all three tables with zero policies, as a forward guard for a future PostgREST/anon access path this plan does not use. It has no effect on this plan's own direct connection, which authenticates as the Supabase `postgres` (owner) role and bypasses RLS by ownership, not by "being direct."

- After every task, run the full suite: `python -m pytest tests -q`. Tests marked `supabase_integration` auto-skip unless `SUPABASE_TEST_DATABASE_URL` is set (Task 2 wires this) — the plan does not require the local Supabase stack to be running for the non-integration tasks, only for Task 4's own integration tests.

```python
"""In-memory test double for the session store — no SQLite, no Supabase, no
I/O. Implements the same five-method contract as the production store
(`backend.app.shared.conversation_store._SupabaseSessionStore`), so tests
can monkeypatch `_store` with this instead of standing up a real database.
"""
from copy import deepcopy


class FakeSessionStore:
    def __init__(self):
        self._data: dict[str, tuple[list[dict], int]] = {}

    def load(self, key: str) -> list[dict]:
        return self.load_with_revision(key)[0]

    def load_with_revision(self, key: str) -> tuple[list[dict], int]:
        messages, revision = self._data.get(key, ([], 0))
        return deepcopy(messages), revision

    def save(self, key: str, messages: list[dict]) -> None:
        _, revision = self._data.get(key, ([], 0))
        self._data[key] = (deepcopy(messages), revision + 1)

    def delete(self, key: str) -> None:
        self._data.pop(key, None)

    def cleanup_old(self, max_age_days: int = 30) -> int:
        # No test exercises real time-based cleanup against this fake today;
        # provided for interface completeness. Add real aging behavior here
        # if a test ever needs it.
        return 0
```

```python
class _SupabaseSessionStore:
    """Postgres-backed session store, reached via a direct `psycopg`
    connection rather than `supabase-py`/PostgREST — `save()` needs a real
    multi-statement transaction (upsert, row lock, delete, bulk insert,
    revision bump) that a sequence of separate HTTP calls cannot provide.

    The constructor performs no I/O. Config is validated and the pool is
    opened only inside `_get_pool()`, on first real use — constructing this
    eagerly at module import time (as the module-level `_store` singleton
    does) must never raise, or every test's ability to monkeypatch `_store`
    before it's used breaks at collection time.
    """

    def __init__(self):
        self._pool: ConnectionPool | None = None

    def _get_pool(self) -> ConnectionPool:
        if self._pool is None:
            if not settings.SUPABASE_DB_URL:
                raise RuntimeError("SUPABASE_DB_URL chưa cấu hình.")
            self._pool = ConnectionPool(
                conninfo=settings.SUPABASE_DB_URL,
                min_size=1,
                max_size=5,
                timeout=5,
                open=False,
                kwargs={"row_factory": dict_row, "connect_timeout": 5},
            )
            self._pool.open(wait=True)
        return self._pool

    def close(self) -> None:
        if self._pool is not None:
            self._pool.close()
            self._pool = None

    def load(self, key: str) -> list[dict]:
        return self.load_with_revision(key)[0]

    def load_with_revision(self, key: str) -> tuple[list[dict], int]:
        with self._get_pool().connection() as conn:
            session = conn.execute(
                "select id, revision from sessions where user_id = %s and client_key = %s",
                (_DEFAULT_PROFILE_ID, key),
            ).fetchone()
            if session is None:
                return [], 0
            rows = conn.execute(
                "select role, content from messages where session_id = %s order by id",
                (session["id"],),
            ).fetchall()
            messages = [{"role": r["role"], "content": r["content"]} for r in rows]
            return messages, session["revision"]

    def save(self, key: str, messages: list[dict]) -> None:
        # One transaction. `with pool.connection() as conn:` commits
        # automatically on clean exit and rolls back automatically if
        # anything inside raises — do not call conn.commit() in this
        # method, doing so would split this into two transactions and
        # defeat the atomicity this whole design exists for.
        with self._get_pool().connection() as conn:
            conn.execute(
                """
                insert into sessions (user_id, client_key)
                values (%s, %s)
                on conflict (user_id, client_key) do nothing
                """,
                (_DEFAULT_PROFILE_ID, key),
            )
            session = conn.execute(
                """
                select id from sessions
                where user_id = %s and client_key = %s
                for update
                """,
                (_DEFAULT_PROFILE_ID, key),
            ).fetchone()
            session_id = session["id"]

            conn.execute("delete from messages where session_id = %s", (session_id,))
            if messages:
                with conn.cursor() as cur:
                    cur.executemany(
                        "insert into messages (session_id, role, content) values (%s, %s, %s)",
                        [(session_id, m["role"], Jsonb(m["content"])) for m in messages],
                    )
            conn.execute(
                "update sessions set revision = revision + 1, updated_at = now() where id = %s",
                (session_id,),
            )

    def delete(self, key: str) -> None:
        with self._get_pool().connection() as conn:
            conn.execute(
                "delete from sessions where user_id = %s and client_key = %s",
                (_DEFAULT_PROFILE_ID, key),
            )

    def cleanup_old(self, max_age_days: int = 30) -> int:
        cutoff = datetime.datetime.now(datetime.timezone.utc) - datetime.timedelta(days=max_age_days)
        with self._get_pool().connection() as conn:
            rows = conn.execute(
                """
                delete from sessions
                where user_id = %s and updated_at < %s
                returning id
                """,
                (_DEFAULT_PROFILE_ID, cutoff),
            ).fetchall()
            return len(rows)
```
